# 月度账务分析同步

用户在对话中要求「总结 26 年 8 月财务数据」时，解读为 2026 年 8 月：读取当前数据、生成总结、同步覆盖该月份归档。其他月份不变，不重复确认，不创建定时任务，不调用外部模型 API。年份存在关键歧义时先明确年份。

## 执行流程

1. 先读取项目规范和当前状态。通过本地已运行接口或 H2 只读连接取得该月及上月的聚合数据；连接要求 `IFEXISTS=TRUE;ACCESS_MODE_DATA=r`。不得为了生成总结启用迁移、修改交易、分类或导入批次。
2. 仅统计 `CONFIRMED` 批次，排除「忽略」，中性交易不计收支。金额用 `BigDecimal` 或 Python `Decimal`；不输出账户、交易对方、摘要及原始账单。保留最早／最晚交易日期、已确认笔数和分类覆盖情况。
3. 生成收支总结、主要变化、待核对事项与下月建议。未分类不等于可削减消费；大额资金流不直接推断成工资、投资收益或消费。交易日期覆盖不能证明账单完整。没有数据的月份不伪造零收支总结，非完整月明确说明不可直接与完整月比较。
4. 将候选 JSON 写入本项目 `.tmp/<task-slug>/`，结构遵循 `AnalysisService.MonthlyAnalysis`。`current` 和 `previous` 含收入、支出、结余；没有上月数据时 `previous=null`。`categories` 包含本月和上月分类并集，本月无支出的分类金额为零；没有上月数据时 `previousAmount=null`。金额使用十进制字符串。`sections` 每项为 `heading`、`text`。
5. 执行 `python3 scripts/publish_analysis.py .tmp/<task-slug>/<month>.json`。脚本核验月份、日期、收支及分类加总，计算结余率、支出环比、分类占比、分类增减，规范中文与英文／数字空格并写入北京时间。验证失败保留原文件；成功后原子替换 `data/analyses/YYYY-MM.json`，不影响其他月份。
6. 请求 `GET /api/analyses/YYYY-MM`，核对内容、金额和更新时间，必要时刷新网站「账务分析」。不得以成功写文件代替网站读取验证；服务不可用时说明读取尚未验证。

## 保存边界

- `data/analyses/` 是正式本地交付物，已被 `data/` 的 Git 忽略规则覆盖。重启、刷新和 `mvn clean install` 不会清理；长期保存仍需用户自行备份磁盘数据。
- 每月保留最近一次总结，覆盖时文字与报表一起替换，不维护历史版本。外部数据库更改不会自动改动既有快照。
- `GET /api/analyses` 返回月份倒序列表，`GET /api/analyses/YYYY-MM` 返回整篇。无数据时列表为空；缺失月份返回 404；月份非法返回 400；归档损坏返回 500，不返回文件原文或磁盘路径。
- 页面将归档文本按纯文本转义展示，不能执行归档中的 HTML。接口仅供本机使用，沿用应用现有访问边界。

## 验证入口

- Java 构建与回归：`JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home mvn clean install`，测试只用隔离内存 H2 或临时文件。
- 同步脚本回归：`python3 -m unittest discover -s scripts -p 'test_*.py'`，覆盖同月替换、跨月隔离、错误金额不覆盖和零分母。
- 实际网站：通过月份导航或选择框切换月报、刷新归档、展开其余分类和页尾口径说明，重启后再读取。核对收支柱状图与分类条形图、数据覆盖说明及更新时间；负结余应在零线下方，非完整月份不展示上月整月的对比图形，零金额不应产生无效图形坐标。页面不展示数据表格。
