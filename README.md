# Personal Finance · 个人财务

一个在自己电脑上运行的财务管理网站。导入微信支付、支付宝和招商银行账单，确认入账后查看收支、分类和交易明细，月底再把总结和图表一起归档。

[快速上手](#快速上手) · [导入账单](#导入账单) · [交易明细和报表](#交易明细和报表) · [账务分析](#账务分析)

*报表首页。本文截图均来自网站演示实例，账单、金额和月报内容均为虚构。*

## 你可以用它做什么

- 上传多个账单文件，或在页面解析 `bill/pending/` 中的待导入文件。
- 支持 ZIP 压缩包、微信支付 XLSX、支付宝 CSV、招商银行 PDF 账单。
- 在交易真正入账前，先查看待确认的导入批次。
- 通过文件哈希和交易业务指纹做双重去重，避免同一份账单重复计算。
- 查看周度、月度、年度和自定义时间范围的收入、支出、结余，并通过分类树状图和时间趋势柱状图观察支出变化。
- 在交易明细中按分类、收支、时间和来源筛选记录。
- 管理交易分类和自动分类规则。
- 在「账务分析」按月阅读杂志式财务月报：关键收支数字、收支对比柱状图、分类支出条形图，以及本月观察和下月建议。总结在对话中生成后同步到本机，重复总结同一月份会覆盖更新，重启后仍保留。
- 对人工分类结果选择是否同步相似交易。
- 将信用卡还款、花呗还款等资金转移识别为中性交易，避免重复计入支出。
- 保留原始账单文件，并按待处理、处理中、已归档、失败等状态管理。

## 项目特点

### 本地优先

账单、交易摘要和账户信息都属于敏感数据。项目默认使用本地 H2 文件数据库，不依赖第三方云端财务服务，也不会在日志中输出完整账单内容。

### 先确认，再入账

上传或扫描账单后，交易关联到待确认批次。只有用户点击确认，交易才会计入报表。

### 两层去重

项目同时检查：

1. 文件级去重：通过原始账单文件的 SHA-256 哈希判断文件是否已经处理过。
2. 交易级去重：通过来源交易流水号和业务指纹判断交易是否已经存在。

重复命中不会悄悄覆盖原数据，批次会保留去重数量和处理结果。

报表页的「重复交易核对」可检查当前周期内同来源内容相同、跨渠道同日同方向同金额的候选。核对范围最多一年，结果只列内部编号、日期、来源、方向、金额和分类；候选需结合原账单判断，不会自动删除或更改统计。跨日结算等情况可能无法命中。

失败批次重新上传相同内容时，若尚无关联交易，可以复用原批次重试；已包含交易的失败批次仍拒绝自动重试，避免重复写入。

### 金额精确保存

金额统一使用 H2 `DECIMAL(19,4)` 保存，不使用浮点数，避免财务计算中的精度误差。

## 技术栈

### 后端

- Java 21
- Spring Boot 4.1.0
- Spring Web：提供 Web 页面访问和 REST API
- Spring Data JPA：访问 H2 数据库
- Spring Validation：参数校验基础能力
- Maven：项目构建和依赖管理

### 数据库

- H2 2.x：使用已有文件保存导入批次、交易、分类和分类规则，日常运行不连接 MySQL。
- Hibernate：启动时仅校验结构，不自动创建或修改表。
- Flyway：默认关闭；隔离的内存数据库测试会显式启用，用于准备测试夹具。

### 账单解析

- Apache POI 5.4.1：解析微信支付 XLSX 文件。
- Apache PDFBox 3.0.5：解析招商银行 PDF 文件。
- Zip4j 2.11.6：读取普通或密码保护的 ZIP 压缩包。
- 支付宝 CSV 使用项目内置 CSV 解析逻辑，并兼容常见 GBK／GB18030 编码。

### 前端

- 原生 HTML
- 原生 CSS
- 原生 JavaScript
- Spring Boot 静态资源目录直接提供页面
- 没有 React、Vue、Node.js 或前端打包步骤

## 支持的账单来源

账单来源使用后端固定枚举 `BillSource`，目前有以下三个值：

| 枚举值 | 页面名称 | 支持文件 |
| --- | --- | --- |
| `WECHAT` | 微信支付 | XLSX |
| `ALIPAY` | 支付宝 | CSV |
| `CMB` | 招商银行 | PDF |

来源不仅用于交易展示和筛选，也会参与自动分类规则匹配。例如，同一个关键词可以只对微信支付生效，也可以配置为适用于所有来源。

## 快速上手

下面的步骤适用于首次安装和日常启动。

### 第一步：准备软件

需要安装以下软件：

- Git：用于从 GitHub 下载项目。
- JDK 21：用于运行 Java 程序。

项目自带 Maven Wrapper，所以一般不需要单独安装 Maven。

可以在终端检查软件是否已经安装：

```bash
git --version
java -version
```

其中，`java -version` 应显示 Java 21 或兼容的更高版本。项目使用 Java 21 编译，建议优先使用 JDK 21。项目使用 H2 保存数据，不需要另外安装 MySQL。

### 第二步：从 GitHub 下载项目

在终端执行：

```bash
git clone https://github.com/Cjim666/personal-finance.git
cd personal-finance
```

### 第三步：确认本地数据目录

默认启动会打开已有的 `data/personal.mv.db`，仅校验表结构。全新安装按第五步显式初始化，已有数据库可直接日常启动。

| 配置项 | 默认值 |
| --- | --- |
| 类型 | H2 文件数据库 |
| 文件 | `./data/personal.mv.db` |
| 用户名 | `sa` |
| 密码 | 空 |

`data/` 已加入 `.gitignore`，里面是本机财务数据，不要提交到 GitHub。

### 第四步：构建并运行测试

macOS 或 Linux 执行：

```bash
./mvnw clean install
```

Windows PowerShell 或命令提示符执行：

```powershell
.\mvnw.cmd clean install
```

这一步会下载依赖、编译项目并运行自动化测试。第一次执行可能需要几分钟，主要时间用于下载依赖。

如果只想运行测试：

```bash
./mvnw test
```

### 第五步：初始化并启动

**仅限全新安装。** 确认 `data/personal.mv.db` 尚不存在，再运行下列命令，显式创建空白 H2 数据库和默认分类。已有数据库请直接执行日常启动命令。

```bash
java -jar target/personal-0.0.1-SNAPSHOT.jar \
  '--spring.datasource.url=jdbc:h2:file:./data/personal;MODE=MySQL' \
  --spring.flyway.enabled=true
```

看到 Spring Boot 启动完成后即可打开页面。以后启动用下面的命令，应用只读取现有库和校验表结构。

```bash
java -jar target/personal-0.0.1-SNAPSHOT.jar
```

### 第六步：打开页面

在浏览器访问：

```text
http://localhost:8080
```

如果看到“个人财务”首页，说明项目已经启动成功。

## 导入账单

可以从页面上传账单，也可以先把账单放入 `bill/pending/`，再从页面触发解析。

1. 打开 `http://localhost:8080`。
2. 在报表工具栏点击「导入账单」。
3. 选择账单后点击「上传并解析」，也可以点击「解析文件夹」处理 `bill/pending/` 中的文件。
4. 在「最近导入批次」查看状态、解析条数和去重条数。
5. 点击「确认入账」，返回报表查看已确认交易和收支统计。

单个上传文件最大 20MB，一次上传请求最大 100MB。支持的文件类型是：

- 压缩包：`.zip`，其中可包含下列账单文件
- 微信支付：`.xlsx` 或 `.xls`
- 支付宝：`.csv`
- 招商银行：`.pdf`

ZIP 最多包含 50 个条目，解压后的受支持账单总大小不能超过 100MB，且不支持嵌套 ZIP。解析完成后，原始 ZIP 会移到 `bill/archive/source-packages/`，内部账单各自形成待确认批次。

打开导入窗口后，页面会列出 `bill/pending/` 中即将解析的文件。每个加密 ZIP 旁都有独立密码框，可以一次为多个不同密码的 ZIP 分别填写；普通 ZIP、Excel、CSV 和 PDF 不显示密码框。密码只随本次解析请求使用，不会写入数据库或日志。

上传、解析和去重阶段不会立即改变正式报表。必须点击确认入账，交易才会计入收入、支出和结余。

## 交易明细和报表

首页展示所选周期的收入、支出和结余。点击「支出分类地图」中的色块，可以按该分类查看交易明细。

报表页提供以下周期：

- 周度
- 月度
- 年度
- 自定义日期范围

右侧支出趋势图会根据报表周期自动切换统计粒度：周报展示所选日期所属月份的每周支出，月报展示所选日期所属年份的每月支出，年报展示以所选年份为结束年份的最近 5 年支出。自定义区间暂不拆分时间趋势。

交易明细默认按时间倒序显示。点击金额或时间表头可切换升降序，筛选后保留当前排序。可以组合使用四类筛选条件：

- 分类：例如餐饮、交通、网购、医疗。
- 收支：收入、支出或中性。
- 时间：开始时间和结束时间。
- 来源：微信支付、支付宝或招商银行。

报表周期决定默认展示的交易范围，交易明细中的时间筛选可以在当前报表结果内进一步缩小范围。

筛选栏会突出显示已选条件。点击控件旁的「×」可单独清除分类、收支、开始时间、结束时间或来源，其他条件保持不变；未设置条件时清除按钮不可用。清除筛选仅改变显示范围，不删除交易。

## 账务分析

在有权限读取本机账务的 AI 编程工具中，可指定一个月份生成并同步月度总结。网站「账务分析」按年份选择，默认当前年；该年已归档的月总结按月份升序从左到右排列，点击月刊阅读。没有归档的年份显示空状态。点击「刷新归档」读取最新内容，无需重启应用。

月报顶部展示月份导航、摘要、收支卡片和两张图表。分类图默认显示前 5 类，其余可以展开。手机窄屏切换为单栏阅读。

图表下方是本月观察、下月行动建议和交易日期覆盖范围，页尾可以展开阅读口径。

图表与文字使用同一次生成的快照；补录账单或改分类后，需要重新总结该月份才会更新归档。没有上月数据或上月支出为零时，不计算支出环比；没有收入时，不计算结余率。非完整月份不展示与上月整月的图形比较。图中金额采用同一刻度，负结余显示在零线下方。

内容长期保存于本机 `data/analyses/YYYY-MM.json`，独立于 H2 表结构及浏览器缓存，不随构建或重启清除。请将该目录与 H2 数据库一起备份；这些文件含敏感财务汇总，不提交 Git，也不上传公开服务。网站只提供读取接口，不接入外部模型或提供在线编辑。

打开月报时，会通过 `GET /api/analyses/YYYY-MM/status` 对比当前月份的收支、分类金额、已确认笔数和日期覆盖。有差异时提示重新总结，保留归档原文与图表；核对接口失败时仍可阅读归档。此检查不比较逐笔交易内容，汇总一致不代表每笔内容都未变化，也不检查上月比较快照。

同步流程与文件约定见 [MONTHLY_ANALYSIS.md](docs/MONTHLY_ANALYSIS.md) 。

## 分类管理

「分类管理」沿用财务月报的卡片样式，上下排列两个区域：

### 交易分类

可以新增、停用或删除普通分类。删除分类时，该分类下的已有交易会自动转为「未分类」，关联的自动分类规则也会一并删除。

「未分类」和「忽略」是系统分类，不能删除或停用。将交易分到「忽略」后，交易仍会保留在明细中，但不会计入收入、支出、结余、分类图或时间趋势统计。

### 自动分类规则

规则由以下条件组成：

- 目标分类
- 账单来源，可限定为微信支付、支付宝、招商银行，或不限定来源
- 交易对方或摘要关键词
- 优先级

导入账单时，系统会根据启用的规则自动分类支出。对某笔交易进行人工分类时，系统还会询问是否把相似支付一起更新；选择同步后，会创建来源限定规则，方便后续账单自动分类。

## 账单文件目录

项目会在运行目录下使用以下目录：

```text
bill/
├── pending/                  # 唯一允许扫描的待导入账单目录
├── processing/               # 页面上传时的临时处理目录，不要手动放文件
├── archived/                 # 确认入账后的原始账单归档目录
├── failed/                   # 解析失败或校验失败的账单
└── archive/source-packages/  # 原始压缩包，仅保留，不参与扫描
```

页面上传会自动处理文件。在「导入账单」窗口点击「解析文件夹」，可以立即扫描 `bill/pending/`；扫描只创建待确认批次，不会自动入账。ZIP 解压出的账单会留在 `bill/pending/`，确认入账后再移到 `bill/archived/`。

同一份账单不要同时放入压缩包和解压后的文件，也不要把账单复制到多个待处理位置。

账单目录已加入 `.gitignore`。不要执行 `git add -f bill/...`，也不要把真实账单提交到 GitHub。

## 数据库运行约定

默认使用 `jdbc:h2:file:./data/personal;MODE=MySQL;IFEXISTS=TRUE`。其中 `MODE=MySQL` 是 H2 的 SQL 兼容模式，不连接 MySQL。`IFEXISTS=TRUE` 要求数据库文件已存在，防止从错误目录启动时新建空库。

`spring.flyway.enabled=false`，自定义 Flyway 配置也遵守此开关；`spring.jpa.hibernate.ddl-auto=validate` 只校验已有结构。日常启动不执行 MySQL→H2 数据迁移、Flyway 升级或 Hibernate 建表。

历史迁移脚本和旧迁移工具源码保留供追溯，不属于日常启动流程。若以后确实需要改动数据库结构或导入旧数据，须单独确认具体范围，不通过默认启动自动执行。

## 关键数据约束

- `BillSource`：`ALIPAY`、`WECHAT`、`CMB`。
- `TransactionDirection`：`INCOME`（收入）、`EXPENSE`（支出）、`NEUTRAL`（中性）。
- `CategoryOrigin`：`AUTOMATIC`（自动规则）、`MANUAL`（人工指定）、`UNCLASSIFIED`（未分类）。
- 金额字段使用 `DECIMAL`，金额值始终保存为非负数。
- 只有状态为 `CONFIRMED` 的导入批次中的交易才会进入报表。
- 原始账单、账户名称、交易摘要和交易对方属于敏感数据。
- 日志和排查工具默认避免输出完整敏感字段。

## 只读数据库检查工具

`DatabaseInspector` 是项目提供的本地只读检查工具，只允许执行预定义命令，不接受任意 SQL，也不提供写入能力。

查看数据库表：

```bash
./mvnw -q -DskipTests spring-boot:run \
  -Dspring-boot.run.main-class=com.java.dev.jim.personal.tool.DatabaseInspector \
  -Dspring-boot.run.arguments="tables"
```

支持的命令：

| 命令 | 用途 |
| --- | --- |
| `tables` | 查看业务表及说明 |
| `columns <表名>` | 查看指定表的字段、类型和注释 |
| `rows <表名> [1-500] [--include-sensitive]` | 查看表数据，默认脱敏 |
| `batches` | 按状态汇总导入批次 |
| `unclassified-expenses [1-500]` | 汇总待分类支出 |
| `classification-summary` | 汇总交易方向、分类来源和金额 |
| `neutral-repayments` | 汇总已识别为中性交易的还款 |

只有在本地安全环境中排障时才使用 `--include-sensitive`。不要把命令输出直接发布到公开渠道。

## 常见问题

### 启动时报数据库连接失败

依次检查：

1. `data/` 目录是否有写权限。
2. 是否有其他 H2 进程占用了同一个数据库文件。
3. 是否有残留的 `*.lock.db` 文件。确认没有 Java 进程使用该数据库后，再处理残留锁文件。

### 启动时报数据库缺失或表结构错误

确认从项目根目录启动，连接的是已有 `data/personal.mv.db`。默认不会新建空库、自动迁移或修复结构；不要删除财务库、切换到其他数据库或开启迁移来绕过错误，先核对路径和当前库结构。首次安装可按快速上手的显式初始化步骤操作。

### 页面打开了，但没有交易

上传账单后，交易首先进入待确认批次。请在「导入账单」窗口中找到批次并点击「确认入账」，确认后的交易才会出现在报表中。

### 账单解析失败

确认文件类型和来源匹配：ZIP 内可放受支持账单，微信支付使用 XLSX，支付宝使用 CSV，招商银行使用 PDF。不同平台导出的账单格式可能随时间变化，解析失败的账单会保留在 `bill/pending/` 以便排查。

### 修改了代码，浏览器还是旧页面

项目页面通过静态资源版本号控制缓存。先停止并重新启动应用，再使用浏览器强制刷新；如果仍然没有更新，可以清理浏览器缓存后重试。

## 安全提醒

- 不要提交真实账单、H2 数据库文件、数据库密码、`.env` 文件或本地配置文件。
- 不要把本地服务直接暴露到公网。
- 不要在日志、Issue、截图或公众号文章中展示完整交易对方、账户名称和账单明细。
- 使用 `DatabaseInspector` 时，除非确认环境安全，不要加 `--include-sensitive`。
- 生产或长期使用前，应补充数据库备份、访问认证和更严格的敏感数据保护措施。

## 当前边界

当前版本暂不包含：

- 用户登录和多用户权限。
- 云端部署和跨设备同步。
- 手机 App。
- 自动从微信、支付宝或银行在线拉取账单。
- 对所有历史账单格式的兼容保证。

项目的定位是一个本地可控、逐步完善的个人财务管理工具。先把账单可靠地导入、去重、确认和统计，再继续扩展其他能力。
